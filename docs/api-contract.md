# 센티멘트 FE ↔ BE API 계약

> 프론트가 기대하는 응답 형태입니다. 타입 원본은 [`src/api/dto.ts`](../fe/src/api/dto.ts) 이고,
> 이 문서와 어긋나면 `dto.ts` 가 기준입니다.
>
> 구조화 추출 결과(`목적`/`대상`/`효과`…)는 **파이프라인이 이미 만들고 있는 스키마 그대로** 받습니다.
> 프론트가 한글 키를 그대로 읽고 [`src/api/mapper.ts`](../fe/src/api/mapper.ts) 에서 화면 타입으로 옮깁니다.
>
> **BE가 아직 없어도 프론트는 돌아갑니다.** `fe/.env` 의 `VITE_API_BASE_URL` 이 비어 있으면
> `fe/src/api/mock/` 의 고정 데이터를 씁니다. mock도 아래와 똑같은 모양이라 매핑 코드를 같이 태웁니다.

## 공통

- JSON, UTF-8. 성공 200, 실패 4xx/5xx
- 날짜는 **`YYYYMMDD` 문자열** (예: `"20260701"`). 화면 표기는 프론트가 `2026. 07. 01` 로 바꿉니다
- **점수·확률 숫자는 화면에 노출하지 않습니다.** `관련도` 는 정렬용으로만 씁니다
- CORS: 개발 서버가 `http://localhost:5173` 이니 이 origin을 허용해 주세요

## 엔드포인트 3개

| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | `/api/regions` | 지자체 목록 |
| GET | `/api/ordinances` | 지역 전체 인덱스 검색 |
| GET | `/api/ordinances/{자치법규일련번호}` | 상세 1건 |

---

## 1. `GET /api/regions`

```json
[
  { "id": "본청", "name": "본청", "fullName": "본청 (전남광주통합특별시)",
    "label": "본청(전남광주통합특별시)", "type": "광역", "totalCount": 366 },
  { "id": "장흥", "name": "장흥군", "fullName": "장흥군",
    "label": "장흥", "type": "기초", "totalCount": 455 }
]
```

`id` 는 이후 모든 요청의 `region` 값입니다. 법제처 지자체코드(org/sborg)와 1:1로 매핑해 두세요.

---

## 2. `GET /api/ordinances`

지역 전체 조례 인덱스 검색. **매칭 테이블이 아니라 지역 전체가 검색 대상입니다** —
본청과 연결되지 않은 조례도 반드시 결과에 나와야 합니다.

| 파라미터 | 예시 | 설명 |
|---|---|---|
| `region` | `장흥` | 필수 |
| `q` | `귀농 지원금` | 비어 있으면 브라우징 모드(해당 지역 전체) |
| `status` | `status=겹침후보&status=확인필요` | 반복 파라미터 |
| `sort` | `relevance` \| `latest` \| `name` | 기본 `relevance` |
| `page` / `pageSize` | `1` / `5` | page는 1부터 |

```json
{
  "items": [ /* 아래 레코드 */ ],
  "total": 12,
  "regionTotal": 12,
  "statusCounts": { "겹침후보": 5, "확인필요": 3, "겹침없음": 4 }
}
```

- `total` — 필터 적용 **후** 건수 (페이지네이션용)
- `regionTotal` — 필터와 무관한 해당 지역 전체 조례 수
- `statusCounts` — 필터 체크박스 옆 숫자. **필터 적용 전** 기준으로 세 주세요

---

## 3. 조례 레코드

검색 결과 1건과 상세 1건은 **같은 모양**입니다.
= 구조화 추출 결과(파이프라인 산출물) + 매칭 결과(Phase 5).

### 3-1. 구조화 추출 부분 — 이미 있는 스키마 그대로

```json
{
  "자치법규일련번호": "2137597",
  "조례명": "전남광주통합특별시 5ㆍ18민주화운동 기념기간 등 국기게양일 지정 및 국기선양에 관한 조례",
  "지역": "본청",
  "목적": "「대한민국국기법」에 따라 … 애국정신을 함양하는 것",
  "대상": {
    "요약": "국기 게양ㆍ관리ㆍ보급ㆍ선양 사업을 시행하는 전남광주통합특별시장과, 국기 무상보급 대상이 되는 취약계층 등 시민",
    "상세조건": [
      "「국민기초생활 보장법」에 따른 수급자",
      "「장애인복지법」에 따른 장애인"
    ]
  },
  "효과": "지정된 날에 국기를 게양하며 … 국기수거함 설치ㆍ운영 등 국기 관리를 시행함",
  "우선순위조항": [],
  "내부충돌여부": false,
  "추출특이사항": "제5조의 '대상'과 실질적 수행 주체가 서로 다른 층위여서 함께 요약함",
  "원문링크": "https://www.law.go.kr/LSW/ordinInfoP.do?ordinSeq=2137597",
  "공포일": "20260701",
  "시행일": "20260701",
  "담당부서": "행정지원과, 자치행정과",
  "전화번호": "061-286-3322, 062-613-2852"
}
```

- 목록은 **배열**로 주세요. (지금 파일이 `{"2263487": {...}}` 형태로 키가 붙어 있다면 값만 배열로 펴서)
- `자치법규일련번호` 가 프론트의 id입니다 — `원문링크` 의 `ordinSeq` 와 같은 값
- `원문링크` 는 상세 화면의 "원문 열기" 버튼이 그대로 새 탭으로 엽니다
- `추출특이사항` 은 상세 화면 하단에 그대로 노출됩니다. 자동 추출이 애매하게 판단한 지점을
  담당자에게 숨기지 않기 위한 항목이라 있으면 반드시 같이 주세요

#### `우선순위조항` 내부 키 — 확정

추출 스키마(`docs/조례_스키마.md`)와 실데이터 기준으로 확정된 모양입니다.

```json
"우선순위조항": [
  { "조문번호": "제8조③",
    "원문": "\"국가 또는 전남광주통합특별시에서 … 우선 적용할 수 있다.\"",
    "유형": "타조례관계",
    "출처": "본청" }
]
```

- `조문번호` / `원문` / `유형`은 추출 파이프라인이 조례 한 건에서 그대로 뽑은 값입니다.
- `출처`는 겹침 판정(3-2)이 있는 레코드에서만 옵니다 — 매칭 단계에서 본청·지역 양쪽
  조례의 우선순위조항을 한 목록으로 합치면서 `"본청"` / `"지역"` 으로 표시해 둔 것입니다.
  겹침 판정이 없는(겹침없음) 레코드는 이 조례 자신의 조항만 오므로 `출처`가 없습니다.
  프론트는 있으면 본청/지역 구분 배지로, 없으면 배지 없이 표시합니다.

### 3-2. 매칭 부분 — 겹침 판정에서 붙는 필드

```json
{
  "판정": "확인필요",
  "분야": "기본소득",
  "관련도": 98,
  "판정근거": [
    "본청 조례와 장흥군 조례 모두 … 중복 적용 검토가 필요합니다.",
    "특히 지급 대상 거주 요건과 수급 기준에서 … 경합 소지가 발견되었습니다."
  ],
  "본청조례": {
    "자치법규일련번호": "2102001",
    "조례명": "전남광주통합특별시 농어촌 기본소득 기본조례",
    "시행일": "20260701",
    "목적": "농어촌 주민의 기본적 생활 안정 및 도농 균형발전 도모",
    "대상": { "요약": "관내 농어촌 지역 1년 이상 계속 거주 주민", "상세조건": ["…"] },
    "효과": "분기별 30만원 상당 지역화폐 또는 계좌 입금",
    "원문링크": "https://www.law.go.kr/LSW/ordinInfoP.do?ordinSeq=2102001",
    "겹침요지": "지원 자격 요건 중복 심사 대상 (거주요건 및 소득 지급 기준 경합)"
  },
  "내부충돌": {
    "제목": "한 조례 안에서 우선순위 조문이 서로 충돌합니다",
    "조항A": { "조문": "제4조 — 이 조례가 우선", "위치": "본조 전문", "내용": "\"…\"" },
    "조항B": { "조문": "제8조③ — 상위 사업이 우선", "위치": "제3항 단서", "내용": "\"…\"" },
    "비고": "두 조문 중 무엇이 우선하는지는 조문만으로 판단되지 않아 자동 판정하지 않았습니다."
  }
}
```

- `판정` 은 `"겹침후보"` | `"확인필요"` | `"겹침없음"` 셋 중 하나 (필수)
- 겹치는 본청 조례가 없으면 `본청조례` 를 빼고 `판정없음사유` 를 채웁니다:

```json
{ "판정": "겹침없음",
  "판정없음사유": "본청 신규 제정 조례 366건 중 같은 취지로 판정된 조례가 없습니다." }
```

  **"겹치는 게 없다"도 유효한 정보이므로 이런 조례를 결과에서 빼지 마세요.**
- `내부충돌여부: true` 인데 `내부충돌` 상세가 없으면 프론트는 경고를 띄우지 않습니다
  (근거 없이 단정하지 않기 위해). 경고를 띄우려면 상세를 같이 주세요.

## 화면이 각 섹션을 언제 그리는지

| 섹션 | 조건 |
|---|---|
| 내부 조문 충돌 경고 | `내부충돌여부 === true` && `내부충돌` 존재 |
| 겹침 없음 안내 패널 | `판정 === "겹침없음"` |
| 광역·기초 대조표 | `판정 !== "겹침없음"` && `본청조례` 존재 |
| 조례 핵심 규정 개요(단독) | 위 대조표가 안 뜰 때 |
| 판정 근거 | `판정근거` 또는 `본청조례.겹침요지` 가 있을 때 |
| 우선순위 조항 | `우선순위조항` 이 비어 있지 않을 때 |
| 추출 특이사항 | `추출특이사항` 이 있을 때 |
